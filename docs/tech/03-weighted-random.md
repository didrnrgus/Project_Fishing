# 03. 가중치 확률과 난수

[← 기술 문서 목차](README.md) · 코드: `Assets/Scripts/Fishing/BiteSelector.cs`, `Assets/Scripts/Data/TournamentRules.cs`

"지금 이 자리에서 무엇이 무나", "AI 낚시꾼은 언제 몇 cm를 낚나"를 정하는 방법들이다.

## 1. 곱셈 가중치 + 룰렛 휠

어종마다 **조건이 맞을수록 커지는 무게**를 곱셈으로 만든다.

```csharp
float w = RarityWeight[s.Rarity];                              // ★1 1.0 … ★5 0.025
w *= Contains(s.Habitats, ctx.Habitat) ? 1f : 0.12f;           // 서식지
w *= Contains(s.Baits, ctx.Bait) ? Mathf.Max(1f, ctx.BaitPotency) : 0.15f;   // 미끼
w *= Contains(s.Times, ctx.Band) ? 1f : 0.3f;                  // 시간대
w *= Contains(s.Weathers, ctx.Weather) ? 1.3f : 1f;            // 날씨
if (ctx.School != null && ctx.School.Contains(s.Id)) w *= ctx.School.BiteBoost;  // 어군 ×2~6
if (ctx.UseSeason) w *= Seasons.BiteFactor(s, ctx.Season);     // 제철 ×1.6 / 철 아님 ×0.35
```

**왜 덧셈이 아니라 곱셈인가**

- 조건이 서로 독립적으로 작용한다. 서식지가 틀리면(×0.12) 미끼가 맞아도 드물다. 덧셈이면 한 조건만 맞아도 꽤 나온다.
- 새 조건(계절, 먼바다, 얼음 구멍)을 **한 줄씩 더하기만** 하면 된다. 다른 줄을 고칠 필요가 없다.
- 0을 곱하면 완전히 막는다: 어군 전용 어종은 어군 밖에서 `return 0`, 먼바다 전용은 먼바다가 아니면 0.
- "불일치"를 0이 아닌 작은 값(0.12, 0.15)으로 둬서 **가끔 의외의 고기**가 나온다. 완전히 막으면 세계가 기계처럼 느껴진다.

### 룰렛 휠 뽑기

```csharp
float r = Random.value * total;
foreach (var (s, w) in list) { r -= w; if (r <= 0f) { picked = s; break; } }
```

- 무게 합 안에서 난수 하나를 뽑아 차례로 빼 간다. O(n)이지만 어종 77개라 충분히 빠르다.
- `picked`를 마지막 원소로 초기화해 두면 부동소수점 오차로 끝까지 r > 0이어도 안전하다.
- 대기 시간(5~14초 × 어군·물때 배율)은 따로 정한다. "무엇이"와 "언제"를 나누면 각각 조정하기 쉽다.

## 2. 비율은 따로 정한다: 잡동사니 문제

처음엔 잡동사니(★0)에도 무게 0.25를 줘서 고기와 같은 룰렛에 넣었다. 그러자 **바다·해외 맵에서 입질의 25~80%가 깡통·운동화**였다.

원인: 고기 무게는 조건이 안 맞거나 희귀 어종이 많으면 아주 작아지는데(0.025 × 0.12 …), 잡동사니 무게는 늘 그대로라 상대 비율이 폭등했다.

해결: **두 단계 뽑기**로 바꿨다.

```csharp
// 1단계: 잡동사니를 뽑을지 확률로 정한다 (맞는 고기가 넉넉할수록 낮다)
public static float JunkChance(float fishWeight, BiteContext ctx)
{
    float p = Mathf.Lerp(0.10f, 0.04f, Mathf.Clamp01(fishWeight));  // 4% ~ 10%
    return ctx.School != null ? p * 0.5f : p;                       // 어군 안은 절반
}
// 2단계: 고른 목록(고기 또는 잡동사니) 안에서만 룰렛
bool pickJunk = fish.Count == 0 || (junk.Count > 0 && Random.value < JunkChance(fishTotal, ctx));
```

> **교훈**: 성격이 다른 결과(고기 vs 꽝)를 한 룰렛에 넣으면, 한쪽 무게가 상황에 따라 크게 바뀔 때 비율이 망가진다. **"어느 쪽인가"를 먼저 확률로 정하고, 그 안에서 고른다.**
> 단위 테스트 `BiteSelectorTests`가 여러 맵·시간대에서 잡동사니 13% 미만을 지킨다.

## 3. 거듭제곱 분포: 대부분 작고 가끔 크다

```csharp
float t = Mathf.Pow(Random.value, skew);   // skew 2.2 (어군이면 1.7~2.0)
float len = Mathf.Lerp(s.MinLen, s.MaxLen, t);
```

- 균등 난수 u를 `u^k`(k > 1)로 바꾸면 0 쪽에 몰린다. k = 2.2면 최대 길이의 90% 이상이 나올 확률이 `1 - 0.9^(1/2.2)` ≈ 4.7%.
- **k 하나로 "대물 확률"을 조절**한다. 어군 안(k 1.7), 해체 미끼(`k - (효력-1)·0.8`), 의상 대물 확률(`k × (1 - 보너스·2.5)`)이 모두 k를 줄이는 방식이다.
- 아래 한계(1.1~1.2)를 둬서 아무리 버프를 쌓아도 균등 분포보다 더 크게 기울지는 않는다.
- 정규분포보다 다루기 쉽다: 범위를 절대 벗어나지 않고, 식이 한 줄이다.

## 4. 포아송 과정: AI 낚시꾼의 조과

대회 AI 7명은 실제로 낚시하지 않는다. 대회 시간(게임 6시간) 동안 **언제 몇 cm를 낚았는지**를 한 번에 만든다.

```csharp
double rate = skill / 45.0;                               // 분당 마릿수 (실력 1.0 = 45분에 한 마리)
while (true)
{
    t += -Math.Log(1.0 - rng.NextDouble()) / rate;        // 다음 입질까지 지수분포 간격
    if (t >= Duration) break;
    // 종류: 희귀도^-1.6 무게로 룰렛, 길이: u^(1.9/실력) — 잘하는 사람일수록 큰 쪽으로
}
```

- **지수분포 간격**(`-ln(1-u)/λ`)을 이어 붙이면 포아송 과정이 된다. 평균은 일정하지만 몰렸다 뜸했다 해서 실제 낚시처럼 보인다. 고정 간격이면 순위표가 기계적으로 바뀐다.
- 실력이 **빈도(λ)와 크기(거듭제곱 지수) 양쪽**에 들어간다. 한 숫자로 개성을 만든다.
- 결과 목록을 시각순으로 정렬해 두고, HUD는 "지금 시각까지의 조과"만 보여 준다.

## 5. 시드 고정 난수: 저장하지 않는 상태

```csharp
var rng = new Random(day * 7349 + (mapId == "honghyeon" ? 17 : mapId == "seocheon" ? 29 : 3));
```

- 같은 날짜·같은 맵이면 **언제 계산해도 같은 결과**다. 그래서 AI 조과를 세이브에 넣지 않는다.
- 게임을 껐다가 다음 날 켜도 정산이 똑같이 나온다(켤 때 정산).
- 테스트도 쉽다: `TournamentRulesTests`가 "같은 날은 같은 결과", "실력 차이가 순위에 드러남"을 확인한다.
- 큰 소수(7349)를 곱해 날짜끼리 시드가 가깝지 않게 한다.

> 전역 `UnityEngine.Random`을 쓰면 다른 시스템(입질, 물보라)이 난수를 소비하는 순서에 따라 결과가 달라진다. **재현이 필요한 계산은 자기 난수기를 따로 가진다.**

## 6. 그 밖에 같은 원리를 쓴 곳

| 곳 | 방법 |
|---|---|
| 포식자 어군 | 게임 2시간마다 18% 확률. 그 맵에서 `힘 × 최대 길이`가 가장 큰 고기 |
| 히든 어군 | 큰 어군이 모두 흩어지면(상태 조건) 나타남. 희귀도 3~4 중 둘 |
| 강화 | 단계별 성공 확률 표 + 별모래 +15%(최대 95%), +7부터 실패 시 10% 하락 |
| 날씨 | 게임 3~7시간마다 다시 뽑기: 맑음 55% · 흐림 27% · 비 18% |
| 빙고판 | 지금 레벨로 갈 수 있는 낚시터의 희귀도 1~3 어종에서 17칸 |

## 옮겨 쓸 때 체크리스트

- 조건은 곱셈 가중치로, 불일치는 0이 아닌 작은 값으로.
- 성격이 다른 결과는 "어느 쪽"을 먼저 확률로, 그다음 그 안에서 룰렛.
- 크기 분포는 `u^k` 하나로, 버프는 k를 줄이는 방식으로.
- 시간에 따른 사건은 지수분포 간격으로.
- 재현이 필요하면 시드를 날짜·장소 같은 상태에서 만들고, 저장하지 않는다.
