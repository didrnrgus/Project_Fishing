## 0. 왜 하나

- **물고기**: 지금 물고기는 무료 팩 모델 3종에 색만 바꿔 쓴다. 폴리곤이 너무 적어서 각지고, 잉어·배스·참돔이 사실상 같은 몸이다.
- **아이템**: 낚싯대, 릴, 줄, 미끼, 배, 김밥, 재료가 상점·가방에 **글자로만** 나온다. 그림이 있어야 게임하는 맛이 난다.
- 원작 「청풍명월」은 도감에 물고기 그림이, 상점·가방에 아이템 아이콘이 있었다.

## 2. 공통 작업 방식: 검색 → 설계 → 제작 → 적용

사용자가 정한 흐름이다. 물고기와 아이템 모두 이 순서를 따른다.

1. **검색**: 실제 물고기 사진, 실제 낚싯대·릴·미끼 사진, 원작 게임 화면을 웹에서 찾아 모양·색·특징을 파악한다.
2. **설계(상상)**: 찾은 자료를 바탕으로 "이렇게 생겼다"를 글로 정리한 **설계 시트**를 만든다(3-3, 4-3의 표). 실물을 그대로 베끼지 않고 게임 그림체로 단순화한다.
3. **제작**: Blender 파이썬(bpy)으로 3D 모델을 코드로 만들고, 미리보기 렌더를 직접 보면서 고친다.
   - 아이템 이미지도 같은 방법으로 3D 모델을 만들어 **렌더해서 아이콘으로 쓴다**. 그래야 조명·각도·그림체가 모두 같다.
4. **적용**: 게임 코드에 연결하고, `tools/build.sh` → `tools/autoshot.sh`로 실제 화면을 찍어 확인한다.

**저작권 규칙**
- 검색한 사진과 그림은 **참고만** 한다. 사진 파일, 다른 게임의 그림, 실제 브랜드 로고·상표명은 게임에 넣지 않는다(공개 저장소).
- 결과물은 우리가 코드로 만든 모델과 렌더뿐이다. 외부 모델을 쓴다면 CC0만 쓰고 출처를 README에 적는다.

**알아둘 한계**
- 손으로 조각하는 게 아니라 수치로 만드는 방식이라, 목표는 "깔끔하게 정리된 사실풍"이다. 비늘 하나하나나 복잡한 근육 굴곡 같은 실사 수준은 어렵다.
- 이미지 생성 AI를 쓰는 게 아니라 3D 렌더로 그림을 만든다.

### 3-2. 몸 형태 틀(무리)과 어종 배정

한 번에 32종을 다 만들지 않는다. 몸 형태가 비슷한 무리별로 **틀**을 먼저 만들고, 그 위에 어종별 차이(비율, 지느러미, 무늬, 색)를 얹는다.

| 틀 | 특징 | 어종 (DB Id) |
|---|---|---|
| A. 잉어형 | 두툼한 몸, 둥근 등, 작은 입, 꼬리 갈라짐 | 붕어(crucian), 잉어(carp), 황금 비단잉어(goldkoi), 누치(nuchi) |
| B. 날씬한 잉어형 | 길고 납작한 몸, 큰 비늘, 은색 | 피라미(zacco), 끄리(kkeuri), 강준치(skygager), 숭어(mullet) |
| C. 농어형 | 가시 있는 등지느러미, 큰 입 | 쏘가리(mandarin), 배스(bass), 블루길(bluegill), 농어(seabass), 볼락(rockfish), 우럭(jacopever), 쏨뱅이(scorpionfish), 쥐노래미(greenling), 자이언트 그루퍼(giantgrouper) |
| D. 도미형 | 높고 옆으로 납작한 몸 | 감성돔(blackseabream), 참돔(redseabream), 돌돔(beakfish), 벵에돔(opaleye), 쥐치(filefish) |
| E. 유선형 | 방추형 몸, 작은 꼬리자루, 갈라진 꼬리 | 고등어(mackerel), 전갱이(horsemackerel), 학꽁치(halfbeak) |
| F. 납작한 고기 | 위아래로 납작하고 두 눈이 한쪽에 있다 | 광어(flounder), 문치가자미(marbledflounder) |
| G. 장어형 | 아주 길고 지느러미가 몸을 따라 이어진다 | 뱀장어(eel), 붕장어(conger) |
| H. 메기형 | 넓적한 머리, 수염, 비늘 없음 | 메기(catfish), 동자개(bagrid), 가물치(snakehead) |

- 잡동사니 6종(빈 깡통, 통발, 나무 상자, 생선 캔, 로봇 물고기, 낡은 운동화)도 같은 방식으로 간단히 모델링한다. 로봇 물고기는 틀 A에 금속 판을 덧댄 모양으로 만든다.
- 어종 목록과 등급은 `Assets/Scripts/Data/FishDatabase.cs`가 기준이다. 어종이 추가되면 이 표에도 넣는다.

### 3-3. 어종별 설계 시트 (검색해서 채울 항목)

어종마다 아래 표 한 줄을 만든다. 자료를 찾으면서 이 문서 아래(부록)에 쌓는다.

| 항목 | 예: 잉어 |
|---|---|
| 참고 자료 | 검색한 사진 설명(파일은 저장하지 않음), 원작 도감 화면 |
| 틀 | A |
| 옆모습 비율 | 몸 높이 / 길이 ≈ 0.3, 등이 머리 뒤에서 완만하게 솟음 |
| 위에서 본 비율 | 몸 폭 / 길이 ≈ 0.16 |
| 머리·입 | 아래쪽을 향한 입, 수염 2쌍(짧은 것·긴 것) |
| 지느러미 | 긴 등지느러미, 갈라진 꼬리, 배·뒷지느러미 붉은 기 |
| 색·무늬 | 등 짙은 올리브 → 옆 금빛 갈색 → 배 연한 노랑, 큰 비늘 테두리가 진함 |
| 눈 | 중간 크기, 금색 홍채 |
| 동작 성격 | 느리고 묵직함 (꼬리 폭 큼, 빈도 낮음) |

### 3-4. 모델링 방법 (bpy, `tools/blender/build_fish.py` 새로 만들기)

1. **몸통**: 머리부터 꼬리까지 단면(타원, 위아래 비대칭) 20~30개를 옆모습·위에서 본 모습 곡선에 맞춰 늘어놓고 이어 붙인다(로프트). 단면마다 버텍스 24~32개.
2. **지느러미**: 얇은 판에 지느러미 살(줄기)을 굴곡으로 넣는다. 등·꼬리·뒷·배·가슴 지느러미를 각각 따로 만들어 몸에 붙인다. 반투명 처리를 위해 지느러미는 별도 머티리얼.
3. **머리**: 입 벌어짐(파이팅 중 입 벌리기용 뼈 하나), 아가미 덮개 선, 눈(구 + 홍채 텍스처).
4. **특징 부품**: 수염(메기·잉어), 가시(쏘가리·쏨뱅이), 납작한 고기의 눈 위치, 장어의 이어진 지느러미.
5. **스무딩**: Subdivision 1단계 후 적용, 법선 정리.
6. **UV**: 옆에서 투영(좌우 대칭)해서 텍스처 하나로 몸 전체를 칠한다.
7. **미리보기**: `--preview`로 옆·위·비스듬한 각도 3장 렌더(`tools/blender/preview.py` 재사용). 이걸 보고 수치를 고친다.

### 3-5. 텍스처

- 코드로 그린다(Pillow/numpy): 등→배 그라데이션, 옆줄, 비늘 격자(육각 패턴 + 테두리 음영), 줄무늬·반점(어종별 규칙), 은빛 반사용 마스크.
- 512×256 정도, 알베도 + 노멀(비늘 굴곡) + 반사도(은색 비늘은 높게).
- 셰이더: 지금 쓰는 Standard로 시작하고, 필요하면 비늘 반짝임(시선 각도에 따른 하이라이트)을 넣은 `Fishing/Fish` 셰이더를 만든다.

### 3-6. 뼈와 애니메이션

- 뼈: 머리 → 몸 4~6마디 → 꼬리자루 → 꼬리. 입(턱) 뼈 1개, 가슴지느러미 좌우 1개씩. 장어형은 몸 마디를 10개 이상.
- 애니메이션은 몸 마디를 사인파로 돌려 만든다(머리 쪽은 작게, 꼬리 쪽은 크게). 어종별 폭·빈도는 Unity 쪽 재생 속도와 가중치로 조절한다.

| 클립 | 동작 | 쓰는 곳 |
|---|---|---|
| `Swim_Slow` | 천천히 헤엄치기, 가슴지느러미 살랑 | 수족관, 도감 미리보기, 대기실 |
| `Swim_Fast` | 빠르게 몸부림치며 헤엄 | 파이팅(물속) |
| `Thrash` | 크게 몸을 비틀며 저항, 입 벌림 | 파이팅 질주·카운터 찬스, 랜딩 직전 |
| `Flop` | 물 밖에서 펄떡이기 | 랜딩, RESULT 화면 |
| `Idle_Hover` | 제자리에서 지느러미만 움직임 | 도감 정지 화면, 박제 대신 살아 있는 연출 |

- Unity 임포트는 지금처럼 Legacy 애니메이션(`AssetImportRules`의 물고기 규칙)으로 시작하고, 필요하면 Generic + Animator로 바꾼다.

### 3-7. Unity 적용

- 결과: `Assets/Resources/Fish/<틀>.fbx` (틀별 FBX) 또는 `<어종 Id>.fbx`. 텍스처는 `Assets/Resources/Fish/Textures/<어종 Id>_*.png`.
- `FishModels.Create`만 바꾸면 파이팅·RESULT·수족관·대기실에 한꺼번에 적용된다. `ModelIndex`(3종 중 고르기)와 `BodyColor`(색만 칠하기)는 어종별 모델·텍스처 선택으로 바꾼다.
- 새 모델이 없는 어종은 지금 Fish1~3으로 돌아가게 해서, 하나씩 바꿔 나갈 수 있게 한다.

### 3-8. 도감 화면

- 지금 도감(`DexPanel`)은 글자만 나온다. 어종을 고르면 **3D 물고기가 `Swim_Slow`/`Idle_Hover`로 천천히 도는 미리보기**를 띄운다. RESULT 화면의 `ResultFishStage`(전용 레이어 카메라 → 렌더 텍스처)를 재사용한다.
- 목록 칸에는 미리 렌더한 **물고기 아이콘**(4장과 같은 규격)을 쓴다. 아직 못 낚은 어종은 검은 실루엣으로 보여 준다.
- 도감 정보(서식지, 좋아하는 미끼, 활동 시간대, 최대 기록)는 그대로 두고 그림 옆에 배치한다.

### 3-9. 진행 순서

1. **잉어 한 마리 시제품**: 모델 + 텍스처 + `Swim_Slow` → 미리보기 렌더를 사용자에게 보여 주고 방향 확인.
2. 잉어를 게임에 넣어 파이팅·RESULT·수족관에서 확인(`autoshot`).
3. 틀 A~H를 하나씩: 틀마다 대표 어종 1마리 → 나머지 어종으로 변형.
4. 애니메이션 5종 완성, 어종별 폭·속도 조정.
5. 도감 3D 미리보기 + 목록 아이콘.
6. 잡동사니 6종.

### 3-10. 완료 기준

- 32종 모두 고유한 모양·무늬가 있고, 사진과 비교해 어종을 알아볼 수 있다.
- 파이팅·RESULT·수족관·대기실·도감에서 새 모델이 나오고 애니메이션이 끊기지 않는다.
- 수족관에 물고기가 가득해도 프레임이 크게 떨어지지 않는다(LOD).
- `docs/images/`의 관련 스크린샷(06_fight, 10_result, 11_dex, 28_aquarium)을 새로 찍어 바꾼다.

### 4-2. 아이콘 규격

- **256×256 PNG, 투명 배경**. 게임 UI에서는 64~96px로 줄여 쓴다.
- 모든 아이콘이 **같은 각도(비스듬히 3/4), 같은 조명(왼쪽 위 주광 + 테두리 빛), 같은 그림체**로 렌더한다.
- 등급·희귀도 테두리나 배경색은 아이콘에 굽지 않고 UI에서 따로 그린다(같은 아이콘을 여러 곳에 쓰기 위해).
- 낚싯대처럼 긴 물건은 대각선으로 눕혀 칸을 채운다.

### 4-4. 제작 방법

- 장비(낚싯대·릴·배)는 게임 속 모델과 같은 형상을 Blender에서 다시 만들거나, 게임 모델 생성 수치를 그대로 옮겨 렌더한다.
- 미끼·음식·재료는 작은 소품이라 간단히 모델링한다(지렁이 = 곡선 따라 튜브, 떡밥 = 울퉁불퉁한 구, 옥수수 = 둥근 낱알 …).
- 스크립트: `tools/blender/build_icons.py` (새로 만들기). 아이템 Id마다 모델 함수 하나, 공통 카메라·조명, `--only <id>`로 하나만 다시 렌더.
- 물고기 아이콘(도감 목록용)도 같은 스크립트로 3장 모델을 옆모습으로 렌더해 만든다.

### 4-5. 게임에 적용

- 파일: `Assets/Resources/Icons/<아이템 Id>.png` (물고기는 `Icons/Fish/<어종 Id>.png`). 임포트 규칙에 Sprite(2D and UI), 알파 투명, 밉맵 끔을 추가(`AssetImportRules`).
- 코드: `ItemIcons.Get(id)` 하나로 불러오고, 그림이 없으면 지금처럼 글자만 보이게 한다(하나씩 채워 나갈 수 있게).
- 아이콘을 넣을 곳:

| 화면 | 위치 |
|---|---|
| 상점(F12) | 각 줄 왼쪽에 아이콘 |
| 가방(I) | 칸마다 아이콘 + 수량 |
| HUD 미끼 바 | 오른쪽 아래 숫자키 칸에 미끼 그림 + 수량 |
| 낚싯대 강화 | 강화할 장비, 재료(비늘·별모래) |
| 교환(소라고동) | 교환 물건 |
| RESULT·보상 토스트 | 얻은 재료·미끼 |
| 도감 | 목록 칸의 물고기 아이콘(3-8) |

### 3-14. 뒤집힌 몸통 면 · 눈 다시 만들기 (2026-10-15)

**증상** (도감 화면 제보): 잉어 머리 한쪽에 눈이 두 개 보이고, 다른 어종도 눈·몸이 이상했다.

**원인**: 몸통 메쉬의 면이 **안쪽을 보고 있었다**(잉어 1728면 중 1426면). Blender 렌더는 뒷면도 그려서 미리보기·아이콘에서는 멀쩡했지만, Unity는 뒷면을 버린다(Cull Back). 그래서 카메라 쪽 몸통이 사라지고 몸 안쪽 벽과 **반대편 눈**이 비쳐 보였다. 조명도 뒤집혀 몸이 어둡고 평평했다. 모든 어종이 같았다.

**수정** (`tools/blender/build_fish.py`):
- `outward_normals()`: 몸통(+눈·수염)을 합친 뒤, 지느러미는 두께를 준 뒤 `bmesh.ops.recalc_face_normals`로 면을 바깥으로 맞춘다. 두족류도 같다.
- **눈**: 반지름 0.65만큼 튀어나온 공 → 머리에 묻힌 납작한 돔(겉으로 0.4, 옆으로 눌러 안쪽 끝이 몸 가운데를 넘지 않음). 전엔 빙어·갈치·전갱이·삼치 등 머리가 얇은 15종은 눈이 반대편 머리를 뚫고 나왔다. 20×12 분할로 더 둥글게.
- 미리보기에 `front_q`(앞쪽 비스듬히, 도감에서 돌 때)·`head`(머리 근접) 장면 추가.

**확인 방법**: Blender에서 Unity처럼 보려면 재질에 "뒷면이면 투명"을 넣어 렌더한다(Geometry › Backfacing → Mix Shader의 Transparent). 수정 전에는 몸통이 깨지고, 수정 뒤에는 정상(잉어·참돔·배스·빙어·전갱이·갈치·가자미·오징어·문어·곰치 확인). 납작한 고기(가자미·광어)는 원래 두 눈이 한쪽에 있다.

> **FBX는 로컬에서 다시 만들어야 한다**: 클라우드 세션은 Git LFS 업로드가 막혀 있어(403) 스크립트만 커밋했다. 3-15의 "로컬에서 할 일"로 텍스처와 함께 한 번에 다시 만든다.

### 3-15. 실사풍으로 끌어올리기 (2026-10-15)

"캐주얼해 보인다"는 피드백으로 같은 파이프라인(코드로 그리는 텍스처 + bpy 모델)을 사실적으로 고쳤다. 어종 수치(`fish_species.py`)는 그대로라 77종에 한꺼번에 적용된다. 잉어로 시제품을 만들고 참돔·고등어·배스·메기로 다른 체형을 확인했다.

| 무엇 | 전 | 후 |
|---|---|---|
| 텍스처 해상도 | 1024×512 (Unity에서 노멀 512·금속성 256으로 더 줄였다) | **2048×1024** (`fish_tex.S = 2`), Unity 알베도·노멀 2048, 금속성 1024, 고품질 압축 |
| 비늘 | 똑같은 반원 도장, 머리까지 덮임 | 비늘마다 자리·밝기·반사가 조금씩 다르다, 드러난 가장자리의 짙은 색소 띠, 덮인 밑동 그늘, 가운데는 옆구리 색(황동·은빛)으로 볼록, 나이테(성장선)·방사선 결. **머리에는 비늘 없음**(아가미 뚜껑 곡선이 경계) |
| 머리 | 비늘 + 아가미 자리에 검은 줄 | 비늘 없는 매끈한 피부와 가는 주름, **아가미 뚜껑 판**(은빛, 관절에서 퍼지는 방사 줄, 전새개골 홈), 뒤 가장자리의 밝은 뼈 턱과 아가미 틈 그늘, 눈 둘레의 꺼진 테, 주둥이 위 진하게, **입술** |
| 바탕색 | 그라데이션 + 잔 노이즈 | 큰 얼룩·중간 결·등쪽 색소 점(1~2픽셀), 배는 따뜻하게, 옆줄 비늘마다 감각 구멍 |
| 광택 | 매끈함 0.42~0.77 | 0.55~0.85 (점액으로 번들), 비늘 볼록한 곳이 더 반짝 |
| 지느러미 | 판에 줄무늬 | 줄기(기조)가 끝으로 가며 둘로 갈라지고 마디가 진다, 막은 밝고 얇아 끝쪽이 비치고 사이사이 해진다, 짙은 끝 가장자리 |
| 눈 | 노란 원 + 검은 원 | 홍채 섬유 결·금빛 반점·짙은 바깥 테·눈 가장자리 피부 (반사는 셰이더가) |
| 수염 | 굵은 상아색 (엄니처럼 보였다) | 가늘고 끝이 뾰족한 살빛 |
| 모델 | 고리 44 × 둘레 28 | 64 × 40 + 아가미 근처 고리 10개, **아가미 뚜껑 판이 몸 위로 덮이는 턱**(뒤 가장자리 앞이 6% 볼록), 삼각형 약 9천 (LOD1은 비율을 낮춰 예전과 비슷) |
| 셰이더 `Fishing/Fish` | 반짝임(_Sheen) | + **무지갯빛**(_Iridescence 0.35): 금속성 비늘에 시선 각도에 따라 파랑 → 보라 → 금빛이 은은하게 |

- 미리보기(`--preview`) 재질도 Unity와 같은 입력(금속성 R·매끈함 A, 지느러미 0.45 잘라내기)으로 바꿔 Blender에서 본 것과 게임이 가깝다.
- 은빛 고기(고등어·전갱이 …)는 반사가 핵심이라 단색 하늘인 Blender 미리보기에서는 차이가 작고, 게임(반사 프로브 + 무지갯빛)에서 확인해야 한다.
- 손볼 곳: 모든 어종에 같은 규칙이라 메기처럼 비늘 없는 고기에도 아가미 뚜껑 방사 줄이 나온다(약하게). 어종별로 끄고 싶으면 `fish_species.py`에 옵션을 더한다.

**로컬에서 할 일** (클라우드는 LFS 업로드가 막혀 FBX·PNG를 못 올린다):
```bash
bpyenv/Scripts/python -I tools/blender/build_fish.py                     # 77종 FBX·텍스처(2048)·아이콘 다시 만들기
bpyenv/Scripts/python -I tools/blender/build_fish.py --only carp --preview   # 잉어 미리보기 (side·top·three_q·front_q·head)
```
그다음 Unity에서 `Fishing > Reimport Fish Assets` → 도감·결과 화면·수족관 확인 → 커밋.
