# 04. 밸런스

## 시뮬레이션 방법

`Assets/Editor/BalanceSim.cs`가 `FishFight`를 그래픽 없이 돌린다. 플레이어 대신 `FightBot`이 싸운다.

- **FightBot**: 장력 0.72 미만이면 감고, 0.9를 넘으면 푼다. 장력 0.8을 넘으면 낚싯대를 물고기 쪽으로 끌어 늦추고, 0.65~0.8에서는 천천히 겨눈다(드래그 장력). 체력이 남은 고기는 6.5m 안으로 당기지 않는다. 낚싯대는 물고기 반대쪽(±0.8)으로 겨누고, 카운터 찬스에는 확률적으로 카운터를 친다. 랜딩 찬스에는 초당 7회 연타한다.
- **사람처럼 반응 지연을 둔다**: 감기/풀기 판단은 0.25초마다만 바뀐다. 낚싯대 조준은 매 프레임 따라간다.
- 어종마다 길이 3종(하위 25%, 대물 기준, 최대) × 장비 7단계(아래 표) × 40회를 돌린다.
- 결과는 [balance-report.md](balance-report.md)에 저장된다.

```bash
sh tools/balance.sh              # 전체
sh tools/balance.sh -simSummary  # 대물 기준/최대 길이만
```

### Unity 없이 돌리기 (`tools/fightsim`)

Unity가 없는 PC·클라우드에서도 같은 시뮬레이션을 돌릴 수 있게 .NET 8 콘솔 도구를 두었다. 게임의 `FishFight`·`FightBot`·어종/장비 DB 소스를 그대로 컴파일하고, UnityEngine은 `Stubs.cs`(Mathf·Random)로 대신한다. 난수 생성기가 Unity와 달라 숫자는 BalanceSim과 몇 %씩 다르지만 경향은 같다.

```bash
cd tools/fightsim
dotnet run -- report                                  # docs/balance-report.md 다시 쓰기 (-simSummary와 같은 표)
dotnet run -- table nileperch,carp 150,190            # 어종·길이를 골라 콘솔에 (최대 시간 열 포함)
dotnet run -- table all - 0.45 1 0.8                  # 체력 20% 이하(지침) 상태로 전 어종
dotnet run -- auto nileperch 158                      # 자동 촬영(Autoplay)과 같은 조건
dotnet run -- bites [hangang]                         # 낚시터·미끼마다 잡동사니가 걸릴 확률 (서식지 4 × 시간대 5 평균, 어군 밖/안)
FIGHTSIM_REACTION=0.5 dotnet run -- table giantgrouper  # 봇 반응을 사람에 가깝게 (기본 0.25초)
```

뒤의 숫자 3개는 플레이어 상태 배율이다: 체력(데미지·카운터·연타, `StaminaFactor`), 내구도(`FightPower`, 낚싯대가 망가지면 0.5), 릴(`ReelFactor`, -1이면 체력 배율을 따름). 지침은 `0.45 1 0.8`, 탈진은 `0.15 1 0.35`.

### 해석
- 원작 영상의 잉어 44cm 파이팅이 약 40초였다. 대물이 20~35초로 비슷한 손맛 길이다.
- 작은 고기는 장비와 관계없이 잡힌다. 대부분 거리를 좁히고 랜딩 연타하는 시간이다.
- 대물을 입문 장비로 노리면 줄이 자주 끊긴다 → **장비를 사야 하는 이유**가 생긴다.
- 상급(연조)과 대물(경조)은 의도적으로 성격이 다르다.
  - 연조: 충격을 흡수해서 거의 안 끊기지만 느리다. 장력이 낮게 유지돼 가끔 바늘이 빠진다.
  - 경조: 데미지가 크고 빠르지만, 질주할 때 장력이 튀어 끊길 수 있다. 대신 비거리가 32m라 데크 끝에서 깊은 칸까지 닿는다.
- **바다 어종**은 민물 대물과 비슷한 20~30초. 돌돔·참돔 최대 크기는 입문 장비에서 85~90%라 장비를 바꿀 이유가 된다.
- **다금바리·돗돔**(홍현 먼바다 전용 전설, 2026-10-14 추가): 다금바리는 그루퍼급. 돗돔은 입문 장비로는 거의 못 올리고 상급 이상이면 다 올린다 — 배 타고 먼바다까지 나가는 끝판 고기로 의도. 무게는 언론 보도(165cm 90kg)에 맞춰 계수 0.02.
- **자이언트 그루퍼**(대물 퀘스트 보스)는 7차(장력 둔감화) 뒤로 봇(반응 0.25초)에게는 어느 장비로나 쉽다. 사람 기준(아래 표, 반응 0.5초)으로 입문 장비면 130cm가 63%, 상급 이상 100%.
- 7차부터 이 표(봇)는 거의 100%라 장비 차이가 잘 안 보인다. 장비 의미는 **사람 기준 표**로 본다.

## 체력 페널티와 파이팅 (2026-10-15)

원작의 체력 2단계 페널티를 넣었다(`PlayerProfile.StaminaFactor`·`ReelFactor`): 체력 20% 이하 "지침"은 데미지·카운터·랜딩 연타 ×0.45, 릴 ×0.8. 5% 이하 "탈진"은 ×0.15, 릴 ×0.35. 낚싯대 내구도가 0이면 데미지 ×0.5.

| 상태 (자동 촬영 조건, 전 어종 × 길이 2 × 장비 7) | 평균 성공률 | 성공률 0%인 칸 | 시간 초과(240초)가 있는 칸 |
|---|---|---|---|
| 체력 정상 | 99% | 0 | 0 |
| 지침 — 수정 전 | 46% | 391 / 1078 | 619 |
| **지침 — 수정 뒤 (랜딩 피로)** | **93%** | 0 | 1 |
| 탈진 — 수정 뒤 | 35% | 300 | 311 |

- **문제**: 랜딩 연타는 한 번에 0.32m × 체력 배율, 초당 7번이면 지침 상태에서 초당 1.0m. 그런데 대물이 되미는 힘은 초당 1.2~1.5m(나일농어 158cm)라 연타로는 영영 못 당긴다. 5m 밖으로 밀려나면 다시 파이팅 → HP는 이미 바닥이라 곧 다시 랜딩 → 끝없이 반복. 자동 촬영의 "나일농어 158cm가 90초 안에 안 끝남"이 이것이었다(앞 장면들의 파이팅으로 체력이 20% 밑으로 떨어져 있었다).
- **조치**: 랜딩에서 버틴 시간을 합산해 12초에 걸쳐 되미는 힘이 25%까지 줄어든다(`FishFight.LandingFatigueTime`·`LandingFatigueMin`). 체력이 정상이면 랜딩이 몇 초 안에 끝나서 거의 영향이 없다(평균 0.4초 짧아짐).
- **탈진은 그대로 가혹하게** 두었다: 원작처럼 "음식을 먹고 다시 하라"는 신호. 사람이면 줄을 풀어 바늘을 빼고 놓아줄 수 있다.
- 회귀 테스트: `FishFightTests.TiredPlayerCanStillLandTrophyFish` (지침 + 대물 장비로 나일농어 158cm 10번 중 7번 이상 — 수정 전 0번, 수정 뒤 10번).
- 자동 촬영은 나일강 장면 앞에서 체력·내구도를 채운다.
